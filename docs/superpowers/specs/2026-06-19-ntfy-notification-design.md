# WowVmMonitor ntfy 通知设计

## 目标

为 WowVmMonitor 增加无需账号密码的 ntfy 通知：

- 固定使用公共服务器 `https://ntfy.sh`。
- 默认主题为 `wow-vm-85898-fan2354`，用户可在设置页修改。
- 仅在状态机产生“异常告警”或“恢复正常”转换时发送。
- ntfy 网络失败、超时或服务不可用不得阻塞或中断任何机器监控。
- 设置页提供异步“测试推送”，显示明确成功或失败结果。

## 配置升级

配置架构从版本 1 升级到版本 2，在根配置中新增：

```json
"ntfy": {
  "enabled": false,
  "topic": "wow-vm-85898-fan2354"
}
```

服务器地址不允许用户编辑，固定为 `https://ntfy.sh`，减少误配置和无关安全面。

现有版本 0 和版本 1 配置自动迁移为版本 2。迁移时保留全部监控和机器设置，ntfy 默认关闭；用户必须在设置页确认主题并启用。原子写入、备份恢复和用户确认规则保持不变。

主题验证规则：

- 不能为空。
- 仅允许 ASCII 字母、数字、下划线和减号。
- 最大长度 64 个字符。

## 组件边界

### App

定义语言中立的通知消息、非阻塞通知队列接口和测试发送接口。设置 ViewModel 增加：

- `NtfyEnabled`
- `NtfyTopic`
- `TestNtfyCommand`
- 测试结果文本

保存仍通过现有异步设置服务，不在 UI 线程执行网络或文件操作。

### Infrastructure

`NtfyClient` 使用一个复用的 `HttpClient`，通过 ntfy JSON 发布接口发送消息。请求超时 10 秒，失败后等待短暂间隔重试一次。

`NtfyNotificationDispatcher` 使用有界 `Channel` 和单一后台消费者：

- 容量 100 条。
- 监控回调只执行非阻塞入队。
- 队列满时丢弃最旧消息并记录可查询失败状态，不阻塞检测。
- 停止监控不销毁发送器；应用退出时停止接收、在有限时间内排空队列并释放 `HttpClient`。

### MonitoringController

仅在 `MonitorTransition.Alert` 和 `MonitorTransition.Recovery` 时创建通知消息并入队。普通、预警、共享不可访问、未找到日志和检测错误不会触发 ntfy。

控制器每次开始监控时重新读取当前配置，并把 ntfy 启用状态和主题应用到发送器。因此设置保存后，停止并重新开始监控即可应用新主题，不要求重启程序。

## 消息格式

异常告警：

- 标题：`WowVmMonitor 异常告警`
- 优先级：高
- 标签：`warning`

恢复正常：

- 标题：`WowVmMonitor 恢复正常`
- 优先级：默认
- 标签：`white_check_mark`

正文包含：

- 机器显示名称
- 当前中文状态
- Windows 本地时间，格式 `yyyy-MM-dd HH:mm:ss`
- 日志年龄（存在时）

正文不包含共享账号、密码、Credential Manager 目标或完整异常堆栈。最新日志完整路径不进入通知，避免泄露网络目录结构。

## 测试推送

用户在设置页输入主题后点击“测试推送”：

- 命令异步执行，窗口保持响应。
- 不要求先启用自动通知。
- 使用当前输入的主题发送标题 `WowVmMonitor 测试通知`。
- 成功显示 `测试通知发送成功。`
- 失败显示稳定的中文错误说明，不直接显示可能包含敏感信息的内部异常。

## 失败处理

- HTTP 非成功状态、DNS、TLS、连接、超时和取消分别转为失败结果。
- 自动通知失败不会抛回监控循环。
- 一台机器的推送失败不影响其他七台机器检测或后续恢复通知。
- 应用退出最多等待 5 秒排空队列，超时后取消剩余发送并继续退出。

## 验证

- 版本 0、1 配置升级到版本 2且机器设置不丢失。
- 非法主题无法保存或发送测试通知。
- Alert 和 Recovery 各发送一次，普通/预警等状态不发送。
- 第一次失败、第二次成功时只产生一次最终成功结果。
- ntfy 请求挂起时八台监控和 UI 仍继续工作。
- 应用退出能在时限内停止发送器。
- 对 `wow-vm-85898-fan2354` 的实际测试推送能在安卓 ntfy 客户端收到。
- Release 构建、完整自动化测试和 Windows 发布包重新生成均通过。
