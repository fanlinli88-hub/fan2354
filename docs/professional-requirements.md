# 魔兽世界共享日志监控专业版需求文档

## 1. 文档信息

- 项目名称：魔兽世界共享日志监控专业版
- 目标平台：Windows 10
- 文档版本：1.0
- 文档日期：2026-06-18
- 需求状态：已确认

## 2. 项目目标

开发一个运行在 Windows 10 主机上的桌面监控程序，通过读取 VMware 虚拟机共享出来的活动日志，判断每台虚拟机中的游戏任务是否持续正常运行，并通过 ntfy 向安卓手机发送异常和恢复通知。

程序最多同时监控 11 台虚拟机。

## 3. 项目范围

### 3.1 包含功能

1. 最多配置和监控 11 台虚拟机。
2. 每台虚拟机可设置自定义名称。
3. 每台虚拟机可设置独立 UNC 共享日志路径。
4. 根据最新活动日志的最后修改时间判断运行状态。
5. 日志连续 5 分钟没有更新时推送异常通知。
6. 异常后日志重新更新时立即推送恢复正常通知。
7. 共享路径不可访问时只在界面显示，不向手机推送。
8. 异常历史保存 7 天。
9. 支持手动开始、停止和单次检测。
10. 支持最小化到系统托盘运行。

### 3.2 不包含功能

1. 不需要开机自动启动。
2. 不开发 Windows 服务。
3. 不截图、不使用 OCR。
4. 不读取或修改游戏进程和内存。
5. 不模拟键盘或鼠标操作。
6. 不自动登录或重新连接游戏。
7. 不解析日志文件正文内容。
8. 不把每分钟产生的正常日志内容推送到手机。
9. 共享路径失败不发送手机通知。

## 4. 监控对象配置

每个监控对象必须包含以下配置：

| 字段 | 类型 | 必填 | 规则 |
| --- | --- | --- | --- |
| 名称 | 文本 | 是 | 不能为空，11 个名称不能重复 |
| 共享路径 | 文本 | 启用时必填 | 必须是 UNC 路径，例如 `\\192.168.1.137\wowlogs` |
| 是否启用 | 布尔值 | 是 | 未启用的对象不检测、不通知 |

全局配置：

| 字段 | 默认值 | 规则 |
| --- | --- | --- |
| ntfy 主题 | 用户填写 | 不能为空，只允许字母、数字、下划线和减号 |
| 检测间隔 | 60 秒 | 每 60 秒检查一次已启用对象 |
| 异常时间 | 5 分钟 | 最新活动日志年龄达到 5 分钟即为异常 |
| 历史保留 | 7 天 | 自动删除超过 7 天的异常历史 |

## 5. 共享日志目录规则

### 5.1 目录示例

```text
\\192.168.1.137\wowlogs
└─ 角色名称
   └─ 2026-06-18
      ├─ 10-0.log
      ├─ 11-0.log
      └─ 12-0.log
```

角色目录中包含日期目录，日期目录中包含按小时产生的 `.log` 活动日志。当前活动日志会持续按分钟或秒写入数据，因此文件的最后修改时间会持续变化。

### 5.2 最新活动日志选择规则

程序对每个共享路径执行以下操作：

1. 只读取共享根目录下的角色目录。
2. 在每个角色目录中选择日期名称最新的目录。
3. 在该日期目录中选择最后修改时间最新的 `.log` 文件。
4. 如果存在多个角色目录，从所有候选文件中选择最后修改时间最新的一个。
5. 顶层组件日志和不在“角色/日期”结构中的日志不参与判断。
6. 不递归遍历全部历史日期和历史日志。
7. 找到最新日志后缓存文件路径，正常检测只读取该文件的最后修改时间。
8. 缓存文件消失或达到异常时间时，重新执行一次浅层查找，以发现跨小时或跨日期产生的新日志。

### 5.3 时间计算规则

```text
日志年龄 = 当前主机时间 - 最新活动日志最后修改时间
```

- 日志年龄小于 5 分钟：正常。
- 日志年龄大于或等于 5 分钟：异常。
- 检测间隔为 60 秒，因此实际通知时间允许落在日志停止后的第 5 至第 6 分钟之间。
- 虚拟机和主机系统时间必须正确，时区应保持一致。

## 6. 状态定义

### 6.1 已禁用

输入条件：监控对象的“是否启用”为关闭。

预期输出：

- UI 显示“已禁用”。
- 不访问共享路径。
- 不进行日志判断。
- 不发送任何通知。

### 6.2 共享不可访问

输入条件：UNC 路径不存在、虚拟机关机、网络不可达、共享权限错误或凭据无效。

预期输出：

- UI 显示“共享路径无法访问”。
- 本次不判断游戏正常或异常。
- 不增加日志异常计时。
- 保留共享中断前最后一个有效游戏状态，不将其改写为正常或异常。
- 不发送手机通知。
- 下一次检测时重新尝试访问，以便路径恢复后自动继续监控。

### 6.3 未找到活动日志

输入条件：共享路径可以访问，但没有找到符合“角色目录/日期目录/活动日志”结构的 `.log` 文件。

预期输出：

- UI 显示“未找到活动日志”。
- 不发送手机通知。
- 下一次检测时重新查找。
- 保留上一个有效游戏状态。
- 该状态不直接等同于掉线，避免目录配置错误造成误报。

### 6.4 正常

输入条件：找到活动日志，并且日志年龄小于 5 分钟。

预期输出：

- UI 显示“正常”。
- 显示最新日志路径、最后修改时间和日志年龄。
- 如果上一个有效状态也是正常，不发送通知。
- 如果上一个有效状态是异常，立即发送一次恢复正常通知。

### 6.5 异常（掉线）

输入条件：找到活动日志，并且日志年龄大于或等于 5 分钟。

预期输出：

- UI 显示“异常：日志已停止更新”。
- 立即发送一次异常通知。
- 在状态保持异常期间，不重复推送每分钟的异常通知。
- 只有恢复正常后再次进入异常，才发送下一次异常通知。

## 7. 启动时状态规则

程序点击“开始监控”或“检测一次”后，立即检查所有已启用对象。

1. 如果最新日志年龄小于 5 分钟，状态为正常，不发送启动通知。
2. 如果最新日志在程序启动前已经超过 5 分钟未更新，立即判定异常并发送异常通知，不重新等待 5 分钟。
3. 如果程序重启时日志仍然异常，允许再次发送一次异常通知，用于确认新启动的监控程序已经发现异常。
4. 如果共享路径不可访问，只显示共享不可访问，不发送通知。

## 8. 通知规则

### 8.1 异常通知

触发条件：监控对象从正常或初始状态进入异常。

通知内容必须包含：

- 监控对象名称。
- 状态：异常。
- 共享路径。
- 最新活动日志路径。
- 最新日志最后修改时间。
- 日志已停止更新的分钟数。
- 通知时间。

### 8.2 恢复通知

触发条件：监控对象从异常恢复为正常。

恢复通知在检测到新日志更新的当次检测中立即发送。

通知内容必须包含：

- 监控对象名称。
- 状态：恢复正常。
- 当前最新活动日志路径。
- 当前日志最后修改时间。
- 恢复通知时间。

### 8.3 通知失败

1. ntfy 推送失败不能中断其他监控对象的检测。
2. 推送失败必须写入本地异常历史。
3. 异常通知发送失败时，下一次检测继续尝试发送，直到发送成功或状态恢复。
4. 恢复通知发送失败时，下一次检测继续尝试发送，直到发送成功。
5. 单次 HTTP 推送最长等待 10 秒。

## 9. 状态转换

| 当前状态 | 输入 | 新状态 | 手机通知 |
| --- | --- | --- | --- |
| 初始 | 共享不可访问 | 共享不可访问 | 无 |
| 初始 | 未找到日志 | 未找到活动日志 | 无 |
| 初始 | 日志年龄 < 5 分钟 | 正常 | 无 |
| 初始 | 日志年龄 >= 5 分钟 | 异常 | 异常通知 |
| 正常 | 日志年龄 < 5 分钟 | 正常 | 无 |
| 正常 | 日志年龄 >= 5 分钟 | 异常 | 异常通知 |
| 异常 | 日志年龄 >= 5 分钟 | 异常 | 无重复通知 |
| 异常 | 日志年龄 < 5 分钟 | 正常 | 恢复通知 |
| 任意有效状态 | 共享不可访问 | 共享不可访问 | 无 |
| 共享不可访问，且此前没有有效游戏状态 | 日志年龄 < 5 分钟 | 正常 | 无 |
| 共享不可访问，且此前有效游戏状态为正常 | 日志年龄 < 5 分钟 | 正常 | 无 |
| 共享不可访问，且此前有效游戏状态为异常 | 日志年龄 < 5 分钟 | 正常 | 恢复通知 |
| 共享不可访问，且此前没有有效游戏状态 | 日志年龄 >= 5 分钟 | 异常 | 异常通知 |
| 共享不可访问，且此前有效游戏状态为正常 | 日志年龄 >= 5 分钟 | 异常 | 异常通知 |
| 共享不可访问，且此前有效游戏状态为异常 | 日志年龄 >= 5 分钟 | 异常 | 无重复通知 |

说明：共享不可访问或未找到日志期间暂停游戏状态判断，并保留最后一个有效游戏状态。共享恢复后，以恢复访问时读取到的实际日志年龄重新判定，并根据最后一个有效游戏状态决定是否发送异常或恢复通知。

## 10. 异常历史

程序只保存重要事件，不保存每分钟的正常检测数据。

必须记录：

- 异常发生。
- 恢复正常。
- 共享路径访问失败和恢复。
- 未找到活动日志。
- ntfy 推送失败。
- 单台检测程序错误。

每条历史至少包含：

- 时间。
- 监控对象名称。
- 事件类型。
- 状态。
- 共享路径。
- 最新日志路径。
- 日志年龄。
- 错误信息（如果存在）。

保留规则：

1. 历史记录只保留最近 7 天。
2. 程序每天至少执行一次自动清理。
3. 删除历史不得影响当前状态和配置。
4. 用户配置持续保存，不能因 7 天清理规则而删除。

## 11. 稳定性与性能要求

1. 最多 11 台虚拟机同时监控。
2. 一台共享路径失败不能中断其他 10 台检测。
3. 一条 ntfy 推送失败不能中断其他对象检测。
4. 文件和网络操作不得长时间阻塞 UI。
5. 正常检测使用缓存文件，不全量扫描历史日志。
6. 空闲状态下不持续占用明显 CPU。
7. 程序连续运行 72 小时不得出现持续内存增长、崩溃或停止检测。
8. 主界面必须显示最后一次完整检测时间。

## 12. UI 功能

主界面必须提供：

1. 11 个监控项的名称、共享路径和启用开关。
2. ntfy 主题配置。
3. 保存配置。
4. 测试推送。
5. 检测一次。
6. 开始监控。
7. 停止监控。
8. 最小化到托盘。
9. 查看异常历史。
10. 每台机器当前状态、最新日志、最后修改时间和日志年龄。

程序关闭规则：

- 点击窗口关闭按钮时最小化到托盘。
- 从托盘菜单选择“退出”才真正结束程序。

## 13. 配置与安全

1. 配置文件损坏时必须提示用户，不能静默使用错误配置。
2. 启用项的名称和路径必须在开始监控前验证。
3. 共享账号密码保存在 Windows 凭据管理器中。
4. 共享密码不得写入普通配置文件、异常历史或通知正文。
5. 共享账号只需要日志目录读取权限。
6. 程序不需要管理员权限即可日常运行。

## 14. 测试要求

每个模块完成后必须先通过自动测试，再进入下一阶段。

### 14.1 核心状态测试

- 日志年龄 4 分 59 秒：正常。
- 日志年龄正好 5 分钟：异常。
- 初次启动且日志年龄 10 分钟：立即异常并通知。
- 异常期间持续无日志：不重复通知。
- 异常后出现新日志：立即恢复并通知。

### 14.2 日志发现测试

- 单角色、单日期、单日志。
- 多角色时选择实际修改时间最新的日志。
- 多日期时选择最新日期目录。
- 跨小时产生新日志。
- 跨日期产生新日志。
- 中文角色目录。
- 顶层无关日志不参与判断。
- 缓存文件消失后重新发现。

### 14.3 故障隔离测试

- 一台虚拟机关机，其他 10 台继续检测。
- 一个共享凭据错误，其他对象继续检测。
- ntfy 不可访问时，全部对象仍继续检测。
- 一台目录结构错误，其他对象继续检测。

### 14.4 真实环境测试

- 1 台虚拟机运行测试。
- 11 台虚拟机同时运行测试。
- 主机断网与恢复。
- 虚拟机断网与恢复。
- 跨午夜运行。
- 连续运行 72 小时。

## 15. 完成与验收标准

项目只有同时满足以下条件才算完成：

1. 可以保存并监控 11 个自定义共享路径。
2. 每个状态均符合第 6 节的输入和输出定义。
3. 日志停止更新达到 5 分钟后，在下一个检测周期内发送一次异常通知。
4. 日志恢复后，在发现恢复的当次检测中发送一次恢复通知。
5. 异常期间不每分钟重复推送。
6. 共享路径失败只显示状态，不发送手机通知。
7. 一台机器失败不影响其他机器。
8. ntfy 失败不影响日志检测。
9. 只保留最近 7 天异常历史。
10. 不需要开机启动，不安装 Windows 服务。
11. 所有自动测试通过。
12. 11 台真实环境测试通过。
13. 连续运行 72 小时无崩溃、无停止检测、无持续资源增长。
14. 使用说明与实际功能一致。
